# AI Social Content Studio
## Desktop AI Content Generation and Rendering Application

**Status:** Build from scratch  
**Platform:** Desktop first  
**Primary OS:** Windows  
**Architecture:** Electron frontend + Python backend  
**Storage:** Local SQLite  
**Rendering:** FFmpeg  
**AI:** DeepSeek API  
**Visual Sources:** Pexels + Unsplash  
**TTS:** Open source local TTS  
**Distribution:** Export for external scheduler such as Metricool  
**Primary Output:** Premium social media videos and images  
**Initial Content Frequency:** Up to 6 content pieces per day

---

# 1. Product Definition

Build a premium desktop application that automatically creates high quality social media content from short form ideas, themes, quotes, and creative directions.

The application is a **local content production studio**, not a social media scheduling platform.

Its responsibility is:

1. Generate the creative concept.
2. Generate the quote/copy.
3. Generate narration.
4. Determine the appropriate visual format.
5. Find suitable visual assets.
6. Avoid repetitive visual assets.
7. Analyze the selected visual.
8. Generate a visual design system for that specific asset.
9. Generate narration audio.
10. Render polished videos and images.
11. Generate platform specific metadata.
12. Present the result in a premium desktop interface.
13. Allow the user to review, regenerate, edit, approve, and export.
14. Save the project locally so it can be reopened later.

The application does **not initially need to publish directly to social networks**.

Generated content should be exported in an organized format suitable for uploading or scheduling through Metricool or another external scheduling platform.

---

# 2. Product Philosophy

The application should feel like a **professional creative tool**, not an AI utility.

Do not build:

- A generic CRUD dashboard.
- A collection of forms.
- A basic admin panel.
- A chat interface with an "Generate" button.
- A generic SaaS dashboard.
- A simple quote over an image generator.
- A collection of cards with gradients and excessive rounded corners.

The product should feel closer to a premium creative desktop application.

The quality target is the level of precision, interaction quality, visual hierarchy, preview experience, motion, and polish found in modern professional desktop creative software.

Use Recordly as a UX quality reference.

Recordly demonstrates an important principle:

> The interface should make complicated media processing feel simple.

Its current architecture combines Electron orchestration with a renderer driven media pipeline, polished preview, motion effects, editing controls, project persistence, and export. The new application should apply the same philosophy to **AI generated social content**, rather than copying Recordly's exact interface. citeturn0search1turn0search5

# 12. DeepSeek Creative Generation

DeepSeek should act as the creative director.

It should generate structured JSON.

Never depend on freeform text parsing.

Example:

```json
{
  "theme": "discipline",
  "quote": {
    "text": "You do not need to feel ready. You need to keep moving.",
    "author": null
  },
  "narration": {
    "text": "You do not need to feel ready. You need to keep moving. Some days the progress is invisible. Keep going anyway.",
    "delivery": "calm_reflective"
  },
  "visual": {
    "preferred_type": "video",
    "search_query": "person walking alone mountain sunrise cinematic",
    "secondary_query": "runner sunrise mountain cinematic",
    "mood": "quiet determination"
  },
  "design": {
    "text_density": "low",
    "animation": "slow",
    "composition": "editorial"
  },
  "metadata": {
    "youtube_title": "Keep Moving",
    "description": "...",
    "hashtags": [
      "#discipline",
      "#mindset",
      "#motivation"
    ]
  }
}
```

DeepSeek should NOT determine exact:

- HEX colors
- Font sizes
- Pixel positions
- Video bitrate
- FFmpeg parameters
- Crop coordinates

Those belong to deterministic application logic.

# 13. Content Quality Rules

Generated quotes must:

- Sound natural.
- Avoid obvious AI phrasing.
- Avoid unnecessary clichés.
- Avoid repetitive structures.
- Avoid excessive punctuation.
- Avoid fake quotations attributed to real people.
- Avoid fabricated authors.
- Avoid repeating recent quotes.
- Avoid producing six variations of the same sentence.

The system should maintain a local history of generated quotes.

Before accepting a new quote, compare it against recent content.

Reject highly similar content.

When generating six pieces, the system should deliberately vary:

- Quote structure.
- Opening.

- Visual type.
- Visual subject.
- Composition.
- Color treatment.
- Animation.
- Narration style.
- Camera movement where applicable.

The six posts should feel like they belong to the same brand without looking like duplicates.

# 16. Asset Selection

Never blindly use the first search result.

The system should:

1. Search multiple candidates.
2. Download metadata first.
3. Filter unsuitable assets.
4. Check previous usage.
5. Calculate similarity.
6. Analyze visual quality.
7. Score candidates.
8. Select the highest scoring eligible asset.

Possible scoring:

```text
semantic relevance       30%
visual quality           20%
composition              15%
brand compatibility      15%
color compatibility      10%
novelty                   5%
motion quality            5%
```

Make these weights configurable.

# 19. Video Asset Rules

Video assets should be evaluated for:

- Resolution.
- Aspect ratio.
- FPS.
- Duration.
- Motion.
- Camera movement.
- Subject position.
- Visual quality.
- Lighting.
- Compression artifacts.

The preferred source is genuine 60 FPS footage.

If a source is 60 FPS:

```text
Preserve 60 FPS.
```

If a source is 30 FPS:

```text
Do not pretend that interpolation makes it genuine 60 FPS.
```

Do not artificially convert every source to 60 FPS merely for marketing purposes.

The application should preserve the source's actual temporal information unless a deliberate interpolation feature is later added.

# 26. Text Placement

Text should be positioned based on the visual.

Example:

```text

→ place text on right.

Subject on right
→ place text on left.

Busy center
→ avoid center.

```

Never place text directly over important facial features or major visual subjects unless intentionally designed.

# 78. Regeneration Threshold

